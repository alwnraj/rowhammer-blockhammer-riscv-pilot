# BlockHammer mitigation pilot in Ramulator 2.0a

This repository contains a **working BlockHammer-versus-baseline DRAM simulation** prepared for a computer architecture course project on RowHammer defenses. It uses the older, pinned [Ramulator 2.0a branch](https://github.com/CMU-SAFARI/ramulator2/tree/legacy/v2.0a); the upstream simulator is downloaded during setup and is not copied into this repository.

The project aims to evaluate BlockHammer in a RISC-V context. **The current pilot is not yet a RISC-V experiment.** Its two traces are supplied by Ramulator and its standalone `BHO3` frontend is a simplified processor model. A future milestone is to feed it traces generated by RISC-V execution or validate an integration with a RISC-V system simulator.

## Run on Linux

Prerequisites: Git, Python 3, CMake, a C++20-capable compiler, internet access for the older pinned build dependencies, and enough memory to compile Ramulator. The upstream source pins `yaml-cpp` 0.7.0, `spdlog` 1.11.0, and `argparse` 2.9. These versions are all older than two weeks; do not replace them with latest releases.

```sh
./scripts/build-linux.sh
./scripts/run-pilot.sh
```

The scripts save new logs in `results/latest/`. The observed pilot logs are preserved in `results/pilot/`. The Linux build has **not yet been verified**; the pilot was run on macOS. If compilation fails, record the exact compiler and error before changing the source.

## Pilot design

The baseline and protected runs share the same DDR5-VRR configuration, RFM manager, two example traces, and 500,000-instruction stopping condition. The baseline has a normal scheduler and no BlockHammer plugin. The protected run enables the BlockHammer plugin and its blocking scheduler. Both omit the example's BLISS plugin to avoid adding a second blacklisting policy.

BlockHammer's Bloom-filter counter threshold is set to **32** rather than the upstream example's 1024 so that the short sample trace visibly triggers the defense. This is an illustrative stress setting, not a measured physical RowHammer threshold. See `experiments/*.yaml` for the full configuration.

| Statistic | Baseline | BlockHammer |
|---|---:|---:|
| Controlling workload retired instructions | 500,000 | 500,000 |
| Controlling workload cycles | 217,439 | 217,439 |
| Hammering core controller row misses | 7,055 | 4,418 |
| LLC blacklist-related allocation retries | 0 | 147,347 |

The protected run recorded **37.4% fewer hammering-core controller row misses** over the same simulated duration. The blacklist statistic counts retry events, not unique accesses. The current logs do not show a per-row activation maximum within a refresh window or simulated bit flips. Do not describe this result as proof that real hardware is protected.

## Project files

- `experiments/`: baseline and BlockHammer configurations, plus the two upstream example traces.
- `results/pilot/`: raw logs from the completed macOS run.
- `scripts/`: Linux build and pilot-run commands.
- `AGENTS.md`: exact status, constraints, and next work for a continuing agent.
- `RAMULATOR_LICENSE`: the upstream MIT notice for the copied example traces and adapted configurations.
