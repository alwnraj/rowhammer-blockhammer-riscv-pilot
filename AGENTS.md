# Agent handoff: BlockHammer / RISC-V RowHammer defense project

## Mission

Continue a CSE 611 computer architecture research project evaluating RowHammer defenses. This repository covers **BlockHammer**, one team member's assigned method. The team chose **Ramulator 2.0**, wants a working simulation for its midterm report, and prefers modest implementation scope. The broader project compares defenses in a RISC-V context; this repository currently contains only the BlockHammer pilot.

## Technical details and limitations

- The standalone Ramulator `BHO3` frontend is a simplified processor model. The repository's example traces are not known to be generated by RISC-V. Present the current result as a DRAM simulation pilot, never as a RISC-V-specific measurement.
- The 32-count Bloom-filter threshold is deliberately lowered to trigger BlockHammer in a short trace. It is not a physical disturbance threshold, and the measured row-miss reduction does not establish bit-flip prevention.
- `llc_mshr_blacklisted` counts blocked/retried allocations, not unique accesses. `controller_core_row_misses_1` is the simulator's row-miss statistic; do not silently relabel it as verified physical ACT commands.
- The current run contains the RFM manager in both configurations. It reported differing counters as traffic changed, so record this when interpreting the comparison.
- On macOS with the available toolchain, building the upstream 2.0a source needed `CMAKE_OSX_SYSROOT` pointing to the Xcode macOS 26.4 SDK, `CMAKE_POLICY_VERSION_MINIMUM=3.5`, a dependent-template spelling fix in `src/base/param.h`, and a format-string compatibility edit in the pinned spdlog dependency. The Linux script applies the template spelling fix; do not assume the remaining Mac-specific edits are needed on Linux.
- Upstream CMake pins `yaml-cpp` 0.7.0, `spdlog` 1.11.0, and `argparse` 2.9. Keep those old versions unless a tested, explicitly justified change is necessary.
